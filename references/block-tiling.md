# 代码切块：把执行流画成一条蛇形回路

> **可跑模板：`templates/recursion-blocks.html`** —— 内置 437 路径总和 III 示例。
> 左栏完整源码逐行高亮，右栏每块 = 一次调用。改题只动 `CODE` / `L` / `run()` / `VARS` / `renderHud`。

递归族现有五种画法：栈帧、递归树、决策树、记忆化砍子树、**代码切块**。前四种画的都是**结构**，切块画的是**执行流**——这是它唯一不可替代的地方。

---

## 一、先判断：切块还是罗列数据

面板式（右栏罗列树 / 栈 / 表：687、437、1038 都是这个路子）和画布式（切块）不是两个技能，是**主次**问题。

**默认走面板式**——它是现有三个模板的默认形态，出错风险最低。只有下面三条里命中任一条，才换成切块：

| 否证条件 | 为什么面板式会失效 |
|---|---|
| **「回到谁、参数是谁给的」成了主要困惑** | 面板里位置固定，返回只是数字变了一下，观众**看不到"回去"这个动作**；切块的块长在左下方，方向本身就是信息 |
| **多层局部值同时活着** | 面板只能摆当前那一层的变量，栈里另外几层各自的 `leftLen`、`sub` 看不见；切块是一层一块，五份平铺在画面上 |
| **结构一屏放不下** | 树高 ≥5 时树形图被压到字都看不清；切块把一条长链摊成斜线，**拿纵向空间换横向空间** |

反过来，满足下面任一条就该留在面板式：

- **有撤销**（`cnt[pre]--`、单调栈弹出、回溯 `pop_back`）——价值全在"少了一格"那一瞬，切块只能让你看见多了一张卡；
- **≥2 个容器同时在变**（前缀和栈 + cnt 表 + 答案）——画布一屏摆不下这么多常驻面板，右栏能并排；
- **要纵向比较**「这一步比上一步多了什么」——位置不动，眼睛不用追。

**可以混**：切块作主画面，右上角挂一个缩小的状态面板（模板里的 `renderHud`）。状态多到角标装不下时，才退回纯面板式。

一句话：**状态钉在原地看变化，流向摊在地上看轨迹。**

## 二、坐标：纵轴是时间，横轴是深度

```js
const BW = 176;  // 块宽
const BH = 56;   // 调用块高
const RH = 30;   // 返回卡高
const DX = 190;  // 每深一层往右挪多少
const GAP = 16;  // 块与块的纵向间距

function layout(blocks) {
  let y = 0;
  blocks.forEach(b => {
    b.h = b.kind === 'ret' ? RH : BH;
    b.x = (b.depth || 0) * DX;   // 横轴 = 深度
    b.y = y;                     // 纵轴 = 第几次事件，顺序排，不回头
    y += b.h + GAP;
  });
}
```

**关键**：`blocks` 是**事件序列**，不是调用栈。进入一次调用 push 一块，返回一次 push 一张卡。所以深度会重复（兄弟节点同深），纵坐标绝不重复——这一条保证蛇形不会纠缠。

`DX` 比 `BW` 大 14px：留出箭头拐弯的余地。`DX < BW` 会让相邻两层的块横向重叠。

## 三、块里只放结果，代码在左栏

早试过把整段函数体塞进块里，结论是**不行**：块高会到 100px，一屏只剩三四块。所以：

```
┌──────────────────────────┐   ← 标题行：圆点 + dfs(值)
│ ● dfs(10)          ↩ 15  │      右上角贴返回值（算完了才出现）
├──────────────────────────┤   ← 1px 分隔线
│ pre 15  need 7  hit 0    │   ← 变量行，最多 3 个
└──────────────────────────┘
```

**变量行必须按字符宽度硬排**，SVG `<text>` 不会自动避让：

```js
// [键名, 标签左边距, 标签到数值的间距]
const VARS = [['pre', 12, 19], ['need', 50, 24], ['hit', 92, 19]];
```

`need` 是 4 个字符，比 `pre`/`hit` 宽，偏移就得单独给。三列等距排的后果是 `need` 的数值压在 `hit` 标签上。

返回卡（`kind: 'ret'`）只画两样：左边 `↩ dfs(值)`，右边 `res N`。绿色虚线框、高只有 30px——**故意矮**，它在视觉上是"收尾"，不该跟调用块一样重。

## 四、相机：常驻 fitAll，不跟随

```js
function fitAll(blocks) {
  const cw = stage.clientWidth, ch = stage.clientHeight;
  const maxX = Math.max(...blocks.map(b => b.x + BW));
  const maxY = Math.max(...blocks.map(b => b.y + b.h));
  const z = Math.min(cw / (maxX + 90), ch / (maxY + 70), 1.34);  // 上限 1.34
  tgt.z = z;
  tgt.x = (cw - maxX * z) / 2;
  tgt.y = (ch - maxY * z) / 2;
}
```

**不要逐块跟随**。试过 `focusBlock`（把当前块拉到屏幕中央）：前几步块少、会放到很大，到第 20 步又突然缩回去，观感很晕，而且看不到"回路"这个整体形状——那才是这个画法唯一的价值。

`z` 上限 1.34 很重要：块少的时候（比如刚开始只有一块）不加限制会放大到 3 倍，块占满屏幕反而看不出方向。

相机用 rAF 做 lerp（`k = 0.2`），新块是"长出来"的而不是"跳出来"的：

```js
function loop() {
  cam.x += (tgt.x - cam.x) * 0.2;
  cam.y += (tgt.y - cam.y) * 0.2;
  cam.z += (tgt.z - cam.z) * 0.2;
  applyCam();
  requestAnimationFrame(loop);
}
```

## 五、箭头：短钩子，只负责指方向

块与块之间只有 16px 的缝，箭头就画成 S 形短钩：

```js
const mid = (y1 + y2) / 2;
h += '<path d="M' + x1 + ' ' + y1 + ' C' + x1 + ' ' + mid + ' ' + x2 + ' ' + mid + ' ' + x2 + ' ' + y2 +
     '" fill="none" stroke="' + col + '" stroke-width="1.5" opacity=".7"' + dash +
     ' marker-end="url(#' + (isRet ? 'arr-r' : 'arr-c') + ')"/>';
```

两个 marker 分别填蓝（`#2f6fd0`，进入）和绿（`#17804a`，返回）。颜色 + 虚线 + 方向三件事同时编码，所以哪怕块缩小到 50%，方向还认得出。

**不要画长箭头连接非相邻的块**（比如从返回卡直接连回它的调用块）。那种线一定会穿过中间好几块，一旦穿过就再也看不清了——返回的方向已经由"往左下"这个位移表达完了。

## 六、坑

1. **每步快照必须带 `line`，且 `line ∈ [1, CODE.length]`**。`verify-demo.js` 会逐帧查，缺一帧就报。
2. **必须解析 `#step=N`**。校验脚本靠它截指定帧，不解析就永远截第 0 帧（空白），你还以为布局没问题。
3. **最后一步快照要带 `ans`（或 `result`）**，才跟 `brute()` 对得上拍。
4. **HUD 放右上角**。放左上会压住第一块——蛇形是从左上往右下长的，左上恰好是起点。
5. **步数会膨胀**。一次调用大约产生 4~6 块（进入、算、左递归、右递归、撤销、返回），所以 7 个节点的树就能到 50 步。要控制在这个量级。
6. **别把整个函数体放块里**（见第三节），也别给每个块加阴影/圆角大半径——块多的时候会糊成一片。
7. **`world.innerHTML = h` 全量重绘**。块数在 50 以内够用；上百块要改成增量，否则播放会卡。

## 七、规模参考

| 内容 | 舒服的规模 |
|---|---|
| 树节点数 | 5 ~ 9 个（超过 9 个，步数破 100，回路长到要缩放才看得全） |
| 总步数 | 40 ~ 120 步 |
| 最大深度 | 5 ~ 6 层（再深，`DX × 深度` 会超过画布宽度，只能靠 `fitAll` 缩小） |

深度超过 6 时，考虑把 `DX` 降到 160、`VARS` 减到 2 个，换取横向空间。
