# 踩过的坑

按「症状 → 病根 → 药方」写。动手前扫一眼，能省掉几轮返工。

## 一、数据/逻辑类

### 1. 每一步都显示最终状态

**症状**：拖到第 3 步，数组已经是排好序的样子；所有步长得一模一样。

**病根**：快照里存的是引用。`a: a` 而不是 `a: a.slice()`。生成器跑完后 `a` 变成最终值，前面所有步跟着一起变。

**药方**：数组 `slice()`，对象 `{...V}`，数组套对象 `.map(x => ({...x}))`。
**自检**：在 `S()` 里故意改一下源数组，如果历史步跟着变，就是没拷干净。

### 2. 高亮跳到错误的行

**症状**：页面能跑，但高亮的行和 `note` 说的不是一回事，或者高亮到空行。

**病根**：行号写死在 `yield` 里。改一行注释、删一个空行，后面全错位。

**药方**：建一张 `L = { readN: 7, ... }` 常量表，`yield S(L.readN, ...)`。改 `CODE` 只改这张表。校验脚本会报越界，但**行号偏了不一定越界**，所以这张表是唯一的防线。

### 3. "序号"和"值"混成一个

**症状**：学生看懂了过程，但一旦数组不是 `1,2,3...` 就懵。

**病根**：页面只画了 `a[i]` 的值，没画下标的行进。

**药方**：数组上方**一定画下标行**。找第 k 个节点这种题，要让「第几个」和「里面装什么」在视觉上分开——左边一列画序号，右边画值。

### 4. 大数失真

**症状**：乘积类题目，演示结果和 C++ 跑出来的不一样。

**病根**：JS 只有 double，`2^53` 以上就不准；`Number` 溢出不报错，直接变 `Infinity`。

**药方**：超过 1e15 的量在页面里标注"约"，或者用 `BigInt`（注意 `BigInt` 不能和 `Number` 混算）。演示输入本来就该小，别拿 `n = 5e5` 的数据做演示。

## 二、布局/绘制类

### 5. 箭头尖看不见

**症状**：线画出来了，但末端是平的，指哪看不出来。

**病根**：SVG 先画、格子后画，箭头终点落在格子内部，被格子盖住了。

**药方**：终点退到格子**外面** 2px。同理，任何压在节点上的装饰（标签、光晕）都要在节点之后画。

### 6. 指针标签被线穿过

**症状**：上方绕的弧线横穿 `prev/cur/nxt` 三层标签，一片狼藉。

**病根**：标签分了三层高度（y=90/112/134），向上绕的弧线抬到 124 直接穿过去。

**药方**：标签只占**一层**，弧线抬到标签之上；同一格有多个指针时用固定 `dx` 横向错开，不要往上下叠。

### 7. 弧线太扁，看着像贴边

**症状**：跨度小的弧线拱高只有 20 多像素，像格子上长了个小包。

**病根**：弧度用了固定值，没跟跨度走。

**药方**：`d = base + k * max(0, dist - 1)`，跨度越大越深；再给个下限（比如 30），别让它贴边。

### 8. 节点在反转过程中"消失"

**症状**：链表演示里某个节点突然不见了，下一步又回来。

**病根**：按 `next` 顺序重排节点。`cur->next = nxt->next` 那一瞬间 `nxt` 没人指向，从遍历序列里掉了出去。

**药方**：**固定槽位**。格子位置永不改变，只改箭头。没人指向它就让它"没有箭头指进来"（红虚线边框），而不是把它挪走。

顺带说：把它挪到"链外"画一栏，用户会问"怎么凭空多出一段"。留原位最不容易误解。

### 9. 整页跟着滚

**症状**：高亮行往下走时，右边数据面板一起往上滑出屏幕。

**病根**：`body` 没锁高度，或者面板没设 `min-height: 0` + 内部滚动。

**药方**：`body { height: 100vh; overflow: hidden }`，`.app` 用 flex column，`main` 加 `min-height: 0`，左右面板各自 `overflow: auto`。

### 10. 变量表跳动

**症状**：某些步里下面板整体往上窜一格。

**病根**：变量表按当前有值的键动态生成，行数会变。

**药方**：`VARS_DEF` 固定键和顺序，没值的显示 `—`。

### 11. 代码注释被右边裁掉

**症状**：行尾注释只露出前半截，后面的字被面板边缘切掉；拉宽窗口也不回来。

**病根**：整行 `white-space: pre`，注释和代码挤在同一行。行宽超过面板宽度后，`overflow: auto` 虽然给了滚动条，但没人会想到去横向滚一行代码。

**药方**：代码和注释**拆成两列**（见 `rendering.md` 第七节）。代码 `white-space: pre` 永不折行，注释 `white-space: pre-wrap` 自己折行，注释起点用 `scrollWidth` 量最长代码行后统一。

**别用"整行折行"解决**：注释折到第二行会紧贴下一行的行号，看起来像下一行的内容，比被裁更难读。

**别用 `getBoundingClientRect().width` 量代码列**：量到的是被列宽压扁后的宽度，算出偏小的值，结果代码压在注释上、字叠字。

### 12. 变量名和数值隔了半个屏幕

**症状**：三个变量并排一行，名字贴左边、值贴右边，读完名字得横跳半个面板才找到值，扫三遍还记不住。

**病根**：`.vars { grid-template-columns: repeat(3, 1fr) }` 配 `.v { justify-content: space-between }`。

**药方**：竖排单列 + 紧凑胶囊：

```css
.vars { display: flex; flex-direction: column; align-items: flex-start; gap: 5px; }
.v { display: inline-grid; grid-template-columns: 40px auto; column-gap: 8px; min-width: 132px; }
```

名字和值之间只留 8px，一行一个，从上往下一眼扫到底。

### 13. 中缝拖到最窄，注释整块消失

**症状**：用户一拖分隔条，注释列被挤成 0，代码看着像没写注释。

**病根**：拖动下限写死（比如 260px），比"代码列 + 注释列"的最小合理宽度还小。

**药方**：下限跟着代码列宽走——`min = --code-col-w + 170`。`resize` 时用 `getBoundingClientRect().width` 实测重算，**不要 `parseFloat('40%')`**，那会得到 40。

## 三、交互类

### 14. 播放中点单步，速度翻倍

**症状**：按了"下一步"之后，播放快得刹不住。

**病根**：播放定时器还在跑，单步又改了 `idx`，两个循环叠加。

**药方**：所有单步、重置操作**第一句先 `stop()`**。

### 15. 改速度要等好几拍才生效

**病根**：用了 `setInterval`，速度改了还得清旧定时器。

**药方**：`setTimeout` 递归，每拍重新读 `speed`。自然生效。

### 16. 按空格页面往下滚

**药方**：`if (e.key === ' ') e.preventDefault();`

### 17. 播放到末尾不结束

**药方**：`tick` 里先判 `idx >= steps.length - 1` 就 `stop(); render(); return;`。再按播放时从头开始（`idx = 0`）。

## 四、工具类

### 18. 校验脚本跑不起来

**症状**：`TRACE 块执行失败: document is not defined`

**病根**：TRACE 块里混进了 DOM 操作，比如在 `run()` 里顺手 `document.getElementById`。

**药方**：TRACE 块只做纯计算。要读页面上的东西，放到块外面传参进来。

### 19. 截图失败 / 生成的图是空的

**症状**：`Access is denied` 或者 0 字节文件。

**病根**：Windows 下 `--screenshot` 用了相对路径。

**药方**：`--screenshot` 必须是**绝对路径**且用反斜杠（`E:\path\shot.png`）；URL 那边反过来，用正斜杠 `file:///E:/path/demo.html`。校验脚本已经处理好了，直接用 `--shot N` 就行。

### 20. 截图里是第一步

**病根**：headless 加载时页面刚 `render()` 完第 0 步就截了。

**药方**：模板已经支持 `#step=N` 深链接，截图带 hash 即可。校验脚本也是这么做的。

## 五、内容类

### 21. `note` 写成空话

**症状**：页面能跑，但学生看完还是不懂。

**病根**：`note` 写成"进入循环"、"判断条件"这种，把代码翻译了一遍，等于没说。

**药方**：`note` 必须带**具体数值**和**因果**。

- 差："栈顶小于当前值，弹栈"
- 好："栈顶是 2 号（值 1），1 < 4 → 成立，2 号的答案确定是 4"

### 22. 步数太多，人看不下去

**症状**：`n = 8` 的题目生出 300 多步。

**药方**：预处理阶段合并（读数组可以每个元素一步，但建表可以一步带过），输入缩到 4~8 个元素。**演示的目的是让人看懂，不是复现全部执行细节。**

### 23. 交付时没说怎么改数据

用户打开页面第一件事就是想换个数组试试。**交付时一定告诉他 `INPUT` 在哪一行**，否则他只能看死数据。
