# 题型 → 画法：从题目特征推导可视化方案

这份文档回答一个问题：**拿到一道题，我怎么知道该画什么图？**

`rendering.md` 讲的是"树怎么摆、弧线怎么绕"，是**画法**。本文讲的是**选型**——先认题型，再定图，最后才是画法。

---

## 这份文档覆盖什么

**25 种题型 + 3 张变体表**，从初级的双指针一直排到中等偏难的 DP 和网络流变体。★ = 中等偏易，★★ = 中等，★★★ = 中等偏难。

| 族 | 覆盖题型 | 难度 |
|---|---|---|
| **递归** | 线性递归（栈帧）· 分治递归（树）· 回溯（决策树）· 记忆化 · 代码切块（蛇形回路） | ★★～★★★ |
| **搜索** | DFS · BFS · 多源 BFS · 拓扑排序 · 并查集 | ★★～★★★ |
| **动态规划** | 一维 · 二维 · 区间 · 树形 · 状态机 | ★★★ |
| **指针** | 滑动窗口 · 相向双指针 · 快慢指针 | ★★ |
| **单调** | 单调栈 · 单调队列 · 堆 | ★★～★★★ |
| **链表** | 7 种变体（反转 / 合并 / 删除 / 环 / 相交 / 回文 / 随机指针） | ★★～★★★ |
| **树** | 8 种变体（遍历 / 层序 / 高度 / BST / LCA / 序列化 / 构造） | ★★～★★★ |
| **图** | 7 种变体（Dijkstra / Bellman-Ford / Floyd / Kruskal / Prim / 二分图 / 网络流） | ★★★ |
| **二分** | 二分查找 · 二分答案 | ★★ |
| **排序贪心** | 排序过程 · 区间贪心 | ★★ |
| **位运算** | 位操作与位图 | ★★ |

**怎么用**：先翻 §十三「速查表」，用"一眼识别"那一列对上号，再跳回对应小节看细节。速查表是一页纸，够用 80% 的场景。

**为什么按这个顺序**：大致按"过程的可视化信息密度"排。递归和搜索每一步形状都在变（树会长枝、路径会进退），最适合动画；位运算每一步只是几个格子翻色，最简单的图就够。

## 零、三步定图法

拿到任何一道题，按顺序问三个问题，不要跳步。

### 第一步：看代码骨架，不看题目故事

题目讲的是"小猫跳台阶"还是"股票买卖"不重要。**看解法代码最外层长什么样**，骨架只有这么几种：

| 骨架长相 | 本质 | 往下查 |
|---|---|---|
| `for` 套 `for`，内层规模随外层缩小 | 枚举 + 剪枝 | 双指针 / 窗口 |
| 一个函数调用自己 | 递归 | §2 |
| `queue.push` / `queue.pop` | 队列驱动 | §3.2 BFS |
| 递归 + 手动 `pop` 撤销 | 回溯 | §2.3 |
| `dp[i] = f(dp[...])` | 填表 | §4 |
| `while (stack...)` 弹 | 单调栈 | §6.1 |
| `while (lo <= hi)` 折半 | 二分 | §10 |
| `while (parent[x] != x)` | 并查集 | §3.5 |

**骨架决定图元**，80% 的题在这一步就定下来了。

### 第二步：找"单调变化量"

算法在跑的过程中，一定有某个东西**只朝一个方向走**。把它找出来，那就是你要让用户盯住的东西：

| 单调变化量 | 典型说法 | 画什么 |
|---|---|---|
| 区间左右端只往右移 | 滑动窗口 | 一个会伸缩的框 |
| 候选区间不断折半 | 二分 | `[lo, hi]` 括号收拢 |
| 已确定区域从一端长出来 | 排序、DP 填表 | 分界线 + 生长区 |
| 路径深度只增不减 | DFS | 栈高度 + 网格着色 |
| 距离层一圈圈扩大 | BFS | 波前 |
| 集合不断合并变小 | 并查集、Kruskal | 森林长成树 |

> **图要画"算法正在改变什么"，不是画"数据长什么样"。**
> 数据长什么样，看一眼输入就知道了，不需要动画。动画的唯一价值是展示**变化**。

### 第三步：配辅助视图

主视图负责"看得懂"，辅助视图负责"对得上代码"。代码里每个被读写的变量，都要在屏幕上有个位置，否则用户会问"这个 `cnt` 是哪来的"。

**别按"取前三个"来砍，按级别来判**（完整分级见 `SKILL.md` 第二节 ③）：

- **A 级**（影响走向 / 承载答案）→ 一律独立开区块，**一个都不能省**
- **B 级**（只服务当前这一行）→ 进变量表
- **C 级**（全程不变的常量、哨兵）→ note 里写一句就够

砍错的代价是非对称的：多画一个区块，读者顶多觉得挤；**少画一个关键变量，读者会在那一行直接断链**——他看见代码里改了一个屏幕上看不见的东西，只能自己脑补，脑补错就整段推不下去。

## 一、图元库

只有九种图元，所有题都是它们的组合。**先认图元，再谈细节。**

| # | 图元 | 视觉 | 天生适合 | 千万别用在这 |
|---|---|---|---|---|
| 1 | **线性行** | 一排方格，下方标下标 | 数组、字符串、一维 DP | 有分支的结构 |
| 2 | **二维表 / 网格** | 正方格阵，行列都有标号 | 二维 DP、迷宫、矩阵 | 稀疏图（空太多） |
| 3 | **横排栈** | 底左顶右，顶部标 `top` | 单调栈、括号、DFS 路径 | 会随机访问中间 |
| 4 | **横排队列** | 头左尾右，两端标 `front/tail` | BFS、单调队列 | 后进先出 |
| 5 | **树** | 根在上，子在下，层间距固定 | 递归、二叉树、堆、决策树 | 有环 |
| 6 | **图** | 节点自由布局，边带箭头和权重 | 最短路、拓扑、连通性 | 树（会画歪） |
| 7 | **固定槽位链表** | 格子排死不动，弧线表达 `next` | 链表、指针改写 | 数组（弧线是多余信息） |
| 8 | **状态机** | 节点 = 状态，边 = 转移条件 | 股票、打家劫舍、自动机 | 状态超过 6 个 |
| 9 | **括号 / 区间条** | 一段被 `[` `]` 夹住的色块 | 二分、区间 DP、窗口 | 无区间语义 |

**组合规则**：一道题通常 = **1 个主动图 + 1~2 个 A 级容器视图 + 1 个变量表**。**视觉分区别超过三块**，但 A 级变量有几个就开几个小区块，并排挤在同一块里就行——分区数量要克制，变量数量不能砍。

## 二、递归族 ★★～★★★

> **可跑模板：`templates/recursion.html`** —— 四种形态各有 tab，改题只需换 `CODE` 与 `run()`。

递归是最容易画错的一族，因为**有三种完全不同的递归形态，图也不一样**。搞混了就画成四不像。

### 2.1 线性递归（阶乘、斐波那契、反转链表）

**识别**：`return f(n-1) * n`，一层只调一次自己。

**关键判断：不要画树！** 很多人一看"递归"就往决策树上想，但线性递归的递归树是一条**斜线**，画成树反而更看不懂。

**主视图：调用栈帧（竖着堆）**

```
┌──────────────┐  ← 栈顶（正在算）
│ f(1) = 1     │
├──────────────┤
│ f(2) = 2*1   │
├──────────────┤
│ f(3) = 3*2   │
├──────────────┤
│ f(4) = ?     │  ← 栈底（等着）
└──────────────┘
```

- 每个帧显示：**参数值 + 当前算到哪 + 返回值**
- 往下调用：新帧从上方推入（动画：下降 + 淡入）
- 返回：栈顶帧高亮，显示 `return 6`，然后**向上飘出**一个箭头指向上一帧的 `*` 位置
- 帧高 52px，宽度按最长表达式自适应，帧间距 6px

**辅助视图**：`n`（当前层）、`depth`（已在栈里几个帧）

**这一步在动什么**：栈的高度。**"递归有多深"就是栈有多高**，这是唯一值得看的信息。

**坑**：
- 只画"调用"不画"返回"——用户看不出结果是**从下往上**冒上来的
- 帧里只写 `f(3)` 不写当前值，等于没画

### 2.2 分治 / 树形递归（归并排序、快排、树遍历、求树高）

**识别**：一次调**两个或以上**自己，或递归对象本身就是树。

**主视图：递归树**

节点包含：**入参**（区间 `[l,r]` 或节点值）+ **返回值**。

```
              [0,5] → 15
        ┌────────┴────────┐
    [0,2] → 6        [3,5] → 9
    ┌───┴───┐        ┌───┴───┐
 [0,1]→3  [2,2]→3  [3,4]→5 [5,5]→4
```

**画法要点**：
- 层 = 递归深度，**层高固定 88px**（要留出返回箭头的空间）
- 同一层的节点按入参左端点从小到大排列，**不要按访问顺序**，否则每层都会重排、看着抖
- 返回时：子节点的值**沿边上行**，画一条从子节点顶部到父节点底部的粗箭头，箭头旁标 `+`/`max`/`*`
- 剪枝（快排为空、区间长度 1）：节点用**虚线框**，不再展开

**这一步在动什么**：值从叶子往上冒。**顺序是后序**——先左、再右、最后自己。

**坑**：
- 返回箭头和树的边画同一条线上，分不清"下去"和"上来"。**下去用细实线，返回用粗箭头 + 不同颜色**
- 节点显示返回值之前，用户不知道它在等什么 → 未计算的节点显示 `?`

### 2.3 回溯（子集、排列、组合、N 皇后、数独、单词搜索）

**识别**：函数末尾有 `path.pop_back()` 或 `used[i] = false`，也就是**撤销**动作。

**主视图：决策树 + 当前路径**

这是所有题型里**视觉信息量最大**的一种，必须三件套一起：

| 视图 | 位置 | 内容 |
|---|---|---|
| 决策树 | 主区 | 每个节点 = 一个决策（选了哪个数），当前路径整条**高亮加粗** |
| 当前路径 | 树旁或底部 | `path = [1, 2]`，用 chip 竖排或横排 |
| 结果集 | 右侧 | 每找到一个解，push 一个 chip |

**画法要点**：
- 树的**当前节点**用琥珀色实心，路径上的祖先用浅琥珀底，未走的分支用灰色
- 撤销（`pop_back`）时，对应节点**变灰 + 加一个"撤回"的滑动动画**，chip 从路径栏消失
- **剪枝的节点打叉（✕）并标一行小字说明原因**（比如「长度已够」），这比任何讲解都直观
- 解的数量多时（子集题 n=10 有 1024 个），**只画"正在探索"的子树**，其他折叠成「+ 还有 N 个分支」

**辅助视图**：`depth`、`path.size()`、`ans.size()`、`used[]` 布尔行

**这一步在动什么**：路径的**长度和内容**。核心动作是「进一格、退一格」，所以要让人看见退回。

**坑**：
- 只画"往前走"不画"往回退"——回溯的灵魂就在退
- 树太宽被挤扁。**横向超过 8 个子节点就把同一层改成两行错位**，或者只展开当前分支

### 2.4 记忆化搜索

**识别**：`if (memo[x] != -1) return memo[x];` 出现在函数开头。

**主视图：递归树 + 缓存命中标记**

- 正常展开的节点：实线框
- **缓存命中的节点：灰底 + ✕ + 一行「命中 memo[3] = 5」，且不再展开子树**（子树折叠成一个虚影）
- 缓存表本身作为一个独立的行或表显示，命中时那一格闪一下

**这一步在动什么**：被"砍掉"的子树。用户看到第二棵相同的子树变成一坨灰影，就懂了记忆化在干什么。

**坑**：缓存命中还继续展开——那就等于没记忆化，图在骗人。

---

### 2.5 代码切块（蛇形回路）★★★

**识别**：递归骨架，且命中下面任一条——

- 观众会问「这是第几次调用 / 现在回到谁那儿了」；
- 好几层的局部变量要**同时**看（每层各揣一份 `leftLen`）；
- 树太宽或太深，压成树形图字就看不清了。

**主视图：一块 = 一次调用，沿蛇形铺开**

- 纵轴 = 时间（第几次事件，顺序排不回头），横轴 = 深度（每深一层右移 `DX ≈ 190`）
- 进入递归 → 新块接在**右下方**，蓝色实线箭头
- 返回上层 → 矮卡片接在**左下方**，绿色虚线箭头
- 块内只放 `dfs(值)` + 最多 3 个局部变量 + 右上角 `↩ 返回值`；**不放代码**，代码在左栏逐行高亮

**这一步在动什么**：调用栈的进与出。观众看着回路一路往右下爬、到头折回左下，就明白了"递归不是同时执行，是一层压着一层"。

**相对递归树的取舍**：递归树一屏能看全分叉，但深度一大就废；切块拿纵向空间换横向空间，深度越大越占优，代价是**分叉结构被摊平**——看不出"树长什么样"，只看得出"执行怎么走"。

**坑**：把整段函数体塞进块（块高破百，一屏只剩三四块）；画跨块的长箭头（必然穿过中间块）；相机逐块跟随（看不出回路形状）；HUD 放左上（正好压住起点那一块）。

**什么时候别用**：有撤销（`cnt[pre]--`、`pop_back`）且"少一格"就是重点时；或者 ≥2 个容器同时在变、需要并排常驻时——这两种留在右栏罗列数据。

> 可跑模板：`templates/recursion-blocks.html`；布局公式、相机与七条坑见 `references/block-tiling.md`。

## 三、搜索族 ★★～★★★

> **可跑模板：`templates/search.html`** —— DFS / BFS / 拓扑排序三个 tab，网格、波纹、DAG 三种底座都有。

### 3.1 DFS（网格、图、岛屿、连通块）

**识别**：`dfs(x,y)` 里四个方向 `dx/dy` 循环 + `visited[x][y] = true`。

**主视图：网格**

格子状态用颜色区分，**必须四种，缺一不可**：

| 状态 | 表现 | 含义 |
|---|---|---|
| 未访问 | 白底灰边 | 还没碰过 |
| 在路径上（栈内） | 蓝底粗边 | 正在探索的这条链 |
| 已访问、已回溯 | 浅灰底 | 走过了，走不通 |
| 目标/答案 | 绿底 | 找到了 |

**这一步在动什么**：那条蓝色的链**沿着网格爬**，遇到死路就**一节节褪成灰**。

**关键动画**：回溯时的**褪色方向是从末端往起点退的**，一格一格退。如果整片同时变灰，用户就看不出"回退"这个动作了。

**辅助视图（三件套）**：

1. **递归栈侧栏**：竖排显示 `(1,2) → (1,3) → (2,3)`，栈顶在上
2. **方向循环**：当前在试第几个方向，用小箭头 `↑ → ↓ ←` 高亮
3. **计数器**：`visitedCount`、`area`（当前连通块大小）、`ans`

**坑**：
- 忘了画"已访问但不是路径"的灰色 —— 这是 DFS 和 BFS 最大的视觉差别
- 网格太小时格子里塞不下数字，**格子边长至少 38px**
- 四个方向循环可以用**格子四条边上的小箭头**表示，正在试的那条高亮，比文字清楚得多

### 3.2 BFS（最短路、层序、最短步数）

**识别**：`queue` + `while (!q.empty())` + 取出一层（`for (int k = 0; k < q.size(); k++)`）。

**主视图：网格（或图）+ 波纹**

**BFS 和 DFS 的图要长得完全不一样**，否则用户永远分不清：

| | DFS | BFS |
|---|---|---|
| 主视觉 | 一条**蓝色的线**在爬 | 一圈**同色的波**在扩散 |
| 颜色 | 单色 + 灰 | **每层一个颜色**（色相递进） |
| 动的东西 | 路径进退 | 波前推进 |
| 辅助 | 栈 | 队列 |

**画法要点**：
- 第 k 层用 `hsl(210 - k*12, ...)` 这一类缓变色，**同一层必须同色**——这是"层"的唯一视觉证据
- 波前边界画一圈**虚线晕边**（或光晕），标上 `dist = k`
- 队列横排在下方，元素是坐标 chip，**出队的 chip 灰掉并划掉**（不是消失，消失就看不出"出过队"）

**辅助视图**：`queue.size()`（= 下一层有几个）、`dist[][]` 距离表和网格同步着色、`step`

**这一步在动什么**：颜色从起点**一圈一圈漫出去**。

**坑**：
- 一格一格随机变色 → 退化成 DFS 的观感，前功尽弃
- 多源 BFS 一定要**所有源同时染同一层颜色**，不能一个源染完再染下一个

### 3.3 多源 BFS（腐烂的橘子、01 矩阵）

**识别**：初始化时把**多个**起点一次性 `push` 进队列。

**主视图**：网格 + **所有源同时出发的波**

多个源的波前用**同样的颜色**（因为它们属于同一层），但每个源的起点标一个小旗子。当两股波相遇时，画一条**虚线分界线**，这就是"最近源"的分界。

**坑**：给每个源不同颜色 —— 那变成了"多起点各自 BFS"，语义完全错了。

### 3.4 拓扑排序（课程表、任务调度）

**识别**：`indegree[]` 数组 + 队列 + 每次出队把邻居入度减一。

**主视图：有向无环图（DAG）**

- 节点按**拓扑层级从左到右**排列（入度为 0 的在最左），而不是随便画
- 边画**直线箭头**，不要弧线（弧线是链表专用，别串味）
- 当前处理的节点：琥珀实心
- **入度直接写在节点下方**：`入度 2`

**辅助视图**：入度表（每个节点一行）、队列、已输出序列（这就是答案，必须显示）

**这一步在动什么**：入度数字**一个个减到 0**，然后节点亮起来进队列。这个"减到 0 就点亮"的瞬间是全图的灵魂。

**坑**：
- 不画入度数字，用户只看到节点乱闪
- 有环时（答案不足 n 个），剩下的节点应该**保留红色边框**并标注「入度永不为 0」

### 3.5 并查集

**识别**：`find()` + `parent[]` + `union()`，或者 `while (parent[x] != x) x = parent[x]`。

**主视图：森林**

- 每棵树是一个连通块，**同一棵树用同一个颜色**
- 根节点标 `根`
- `find` 时画的是一条**从节点爬到根的高亮路径**
- `union` 时两棵树之间画一条**粗的合并箭头**，然后两棵树重排、变成一个颜色

**辅助视图**：`parent[]` 数组行（下标 → 父节点）、`集合数`

**这一步在动什么**：树在**合并**，颜色在**融合**，集合数在**减少**。

**路径压缩**：压缩那一刻，画**节点到根的直线闪现**（原来的折线路径淡出）。

**坑**：只画 `parent` 数组不画树 —— 数组看不出"合并"这件事的规模感。

## 四、动态规划族 ★★★

DP 的画法核心只有一句：**箭头指向"这个值是从哪些格子来的"**。这是 DP 可视化唯一的真正信息量。

### 4.1 一维线性 DP（爬楼梯、打家劫舍、最大子段和）

**主视图：一行格子 + 依赖箭头**

```
 dp[1]  dp[2]  dp[3]  dp[4]  dp[5]
   1      2      ?      ·      ·
          ↑↖
          └─┴── 都指向 dp[3]，箭头标 "+"
```

- 当前格：琥珀实心，显示 `dp[i] = 3`
- **依赖箭头从左往右跨格**（沿格子下方绕，和链表的绕线规则一致）
- 算完的格子底色变浅，未算的显示 `·`

**辅助视图**：`i`、转移方程原文（贴在表下方，如 `dp[i] = dp[i-1] + dp[i-2]`）、`ans`

**这一步在动什么**：一个**从左往右推进的竖线**（已算区 / 待算区的分界）。

**坑**：
- 不画箭头，用户只看到数字冒出来，不知道依据
- 滚动数组优化后（只留 3 个格子），要**说明格子被覆写**，否则数字突然变了很惊悚

### 4.2 二维 DP（LCS、编辑距离、背包、最小路径和）

**主视图：二维表**

这是最能体现"填表"的图，也是**最容易画成纯表格**的一种。要点：

- 行列都标下标，**行 = i，列 = j**，头部固定不随滚动
- 每个格子显示 `dp[i][j]` 的数值
- 当前格：琥珀实心 + 外发光
- **依赖箭头从来源格指向当前格**（左上、上、左，按转移方程实际有几个来源）
- 已算区：白底；未算区：极浅灰；**正在算的这一行：浅蓝底**
- 答案格（`dp[n][m]`）最后用绿框圈出

**辅助视图**：`i`、`j`、**转移方程原文**、`a[i]` 和 `b[j]` 两个字符在行列头高亮

**这一步在动什么**：一个**从左到右、从上到下的扫描点**，身后留下一片已填区域。

**填表顺序特别重要**：一定要按代码真实的循环顺序动。如果是背包倒序枚举容量，格子就**从右往左**亮，这个"倒着填"正是 0/1 背包的关键，画错就白画了。

**坑**：
- 表太大（50×50）画不下 → **只显示窗口化的 8×8 区域**，跟着当前格滚动
- 三个来源的箭头交叉成一团 → 箭头用不同颜色的短弧，且**只画当前格的**，历史箭头淡出

### 4.3 区间 DP（戳气球、最长回文子串、石子合并）

**识别**：`for (len = 2..n) for (l...) { r = l + len - 1; ... }`，也就是**按长度枚举**。

**主视图：三角表**

用右上三角（或左上三角）矩阵，**`len` 是这个图的第三维，用颜色渐变表示**：

- 对角线（`len=1`）先亮
- 每条斜线是一轮，**同一轮同色**，像波一样从对角线往右上角推
- 当前区间 `[l, r]`：在下标行上用一段**色块**标出，同时在三角表里高亮对应格

**辅助视图**：`len`（当前长度）、`l`、`r`、分割点 `k`（如果是枚举分割点的题，`k` 要在区间色块里**来回扫**）

**这一步在动什么**：**斜线一条条往右上推**。这就是"按长度枚举"的视觉化，一眼就懂为什么外层是 `len`。

**坑**：把区间 DP 画成普通二维表（按 `i` 行 `j` 列顺序扫）—— 那和代码的枚举顺序不符，会误导。

### 4.4 树形 DP（打家劫舍 III、树的直径、最大路径和）

**识别**：递归函数里返回的是**一对值**（选/不选、最大/次大），父节点用子节点的返回值做决策。

**主视图：树 + 每个节点的返回值**

- 每个节点**下方挂两个小格子**：`选: 5` / `不选: 7`（按题目实际含义命名）
- 后序遍历：子节点的两个格子先填满，父节点才能填
- **当前节点**：琥珀色，正在读子节点的哪个值，就高亮哪个格子

**辅助视图**：`depth`、后序访问序列

**这一步在动什么**：值**从叶子往上冒**，每个节点冒出**两份**。两份值的对比就是决策过程。

**坑**：只显示一个返回值 —— 树形 DP 的精髓就在"两种状态"并存，只显示一个就退化成普通递归了。

### 4.5 状态机 DP（股票买卖、打家劫舍、买卖股票含冷冻期）

**识别**：`dp[i][0]` / `dp[i][1]` 这种**第二维是状态**的写法，或者注释里出现「持有 / 不持有」。

**主视图：状态转移图**

不是表格，是**图**：

```
     ┌──────── 买入 ────────┐
     ↓                      │
  [持有] ←────────────→ [不持有]
     │     卖出              ↑
     └───────────────────────┘
        每天必须选一条边
```

- 状态节点：圆角矩形，当前状态**实心**
- 边：标转移条件（`买入` / `卖出` / `等待`）
- **每天推进一格**：当前天数的状态节点亮，然后跟着一条边跳到下一天的状态

**辅助视图**：`i`（第几天）、`dp[i][0]`、`dp[i][1]`、当天的价格

**这一步在动什么**：一个**token 在状态之间跳**，一天跳一次。

**坑**：状态数超过 6 个还画图 → 改成表格 + 高亮行；图会糊。

## 五、指针族 ★★

### 5.1 滑动窗口（最长无重复子串、最小覆盖子串、定长窗口）

**识别**：`while (r < n) { ... while (条件不满足) l++; }`，两个指针**同向**移动。

**主视图：线性行 + 一个会伸缩的框**

- 数组一行方格，下标标在下方
- 窗口用**一个半透明色块 + 上下两条横线**框住 `[l, r]`，不要用边框（会挡字）
- `l` 和 `r` 各带一个**向下的三角箭头**指着格子
- **窗口内**：浅蓝底；`l` 和 `r` 所在的格子：加粗边

**辅助视图（这题的关键）**：`count[]` 计数表 / `unordered_map` 的键值、`窗口长度`、`ans`、`l`、`r`

**这一步在动什么**：框的**左右边界交替推进**，有时变长有时变短。**这个"缩一下再涨"的节奏就是滑窗的全部**。

**坑**：
- 只画两个指针不画框 —— 看不出"窗口"这个实体
- 更新 `ans` 的瞬间不标出来 —— 用户不知道答案是在哪一步刷新的（应该在那一步闪一下 `ans`）

### 5.2 相向双指针（两数之和 II、三数之和、盛水容器、接雨水、回文判断）

**识别**：`while (l < r)`，一个从头、一个从尾。

**主视图：线性行 + 两端向内的箭头**

- `l` 箭头从左侧指向右（`→`），`r` 箭头从右侧指向左（`←`），**箭头方向本身就表示运动方向**
- 被排除的格子**变灰并收缩**（`transform: scale(0.85)`），留一个空位出来，表示"永久出局"
- 相遇时两个箭头**合并成一个高亮标记**

**辅助视图**：`sum = a[l] + a[r]`、比较结果（`sum < target → l++`）、`area`（接雨水是柱子高度）

**这一步在动什么**：**可搜索区间在两端同时塌陷**。

**坑**：被排除的格子直接消失 → 位置会跳，用户会晕。保持占位，只变灰。

### 5.3 快慢指针（链表中点、环检测、删除倒数第 n 个）

**识别**：`slow = slow->next; fast = fast->next->next;`

**主视图：固定槽位链表**（见 `rendering.md` 第四节）

- 两个指针标签 `slow` / `fast` 用不同颜色
- **加一条"步数差"的标尺**：在链下方画一条横线，标 `fast 走了 8 步 / slow 走了 4 步`，这样"倍数关系"看得见

**环检测（Floyd）**：把链表画成**环形布局**（节点摆在一个圆上），环外部分是一条进入圆环的尾巴。快慢指针在环里**追赶**，相遇时两个标签合在一起闪一下。

**坑**：环检测用直线布局画 → 快指针会跑到画布外面，完全没法看。

## 六、单调族 ★★～★★★

### 6.1 单调栈（下一个更大元素、每日温度、柱状图最大矩形、接雨水）

**识别**：`while (!st.empty() && a[st.top()] < a[i]) st.pop();`

**主视图：横排栈**（见 `rendering.md` 第三节）

- 栈里显示**下标 + 值**两层
- 单调性用**背景渐变色**强化（从深到浅），一眼看出"越往右越矮"
- **弹出时**：栈顶元素向上飘出 + 淡出，同时右侧「已结算名单」多一条 `下标 2 → 答案 5`
- 当前 `a[i]`：数组里琥珀高亮，并画一条**竖线**从它指向栈（表示"我正在弹你们"）

**辅助视图**：`i`、`栈内元素数`、判定（`栈空/可以弹/不弹`）、`ans[]` 答案行（和数组对齐，**逐格填**）

**这一步在动什么**：栈**长高**又**被弹空**，答案行**逐格填满**。

**坑**：见 `pitfalls.md` 第 5~8 条，以及"弹空 ≠ 重置"这条 —— 弹出的元素必须**留下答案的痕迹**，否则看起来像重置。

### 6.2 单调队列（滑动窗口最大值）

**识别**：`deque` + `while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();` + `while (dq.front() <= i-k) dq.pop_front();`

**主视图：横排队列表 + 窗口框（两个视图叠在一起）**

这一题必须**同时**画两个东西，缺一个就讲不清：

1. 上方：数组 + 滑窗框（`l`、`r`）
2. 下方：双端队列，队头在左

- **队尾出队**（新元素更大，挤掉前面的）：从右侧弹出，箭头向下
- **队头出队**（过期）：从左侧弹出，标「过期 i-k」
- 队头元素**永远**是当前窗口最大值，用绿底框住，并画一条线指向答案行

**辅助视图**：`i`、`窗口`、`队头值`、`ans`

**这一步在动什么**：队列**两端都在动**——左边过期、右边挤人。这是它和普通队列最大的区别，一定要让用户看见两端。

**坑**：只画队列不画窗口 → 不知道"过期"是怎么判断的。

### 6.3 堆（前 K 个、中位数、合并 K 条链表）

**识别**：`priority_queue`，`push` / `pop` / `top`。

**主视图：完全二叉树**

**堆必须画成树，不能画成数组**——数组看不出"上浮/下沉"这件事。

- 完全二叉树，层序编号，节点里显示值和下标
- `push`：节点先在树底出现（绿底），然后**沿路径上浮**，每比较一次，父子两个节点闪一下，交换时两个节点**横向滑动交换位置**
- `pop`：根节点高亮后消失，**最后一个叶子节点飞到根**（画一条弧线），然后**下沉**
- 堆序性质：父节点永远 ≥（或 ≤）子节点，用**边上的小箭头**从大到小表示

**辅助视图**：`堆大小`、`堆顶`、数组形式（下方并排显示，体现"树和数组是同一个东西"）

**这一步在动什么**：一个节点在树里**往上爬或往下沉**。

**坑**：用数组画堆 —— 上浮下沉全看不见。

## 七、链表族 ★★～★★★

统一用「固定槽位 + 弧线」（`rendering.md` 第四节，模板待补）。

| 题型 | 主视图 | 特有要素 |
|---|---|---|
| 反转 / 局部反转 | 固定槽位链 | `prev/cur/nxt` 三层标签；悬空节点红虚线 |
| 合并两链 | **两条链上下并排**，各带游标 | 结果链在下，每次取头插进来 |
| 删除节点 | 固定槽位链 | 前驱高亮 + 被删节点的入箭头变红后消失 |
| 环检测 | **环形布局** | 快慢标签 + 步数差标尺 |
| 相交链表 | **Y 字形布局** | 两条尾巴汇合点高亮；长度差用括号标 |
| 回文链表 | 链 + 反转后的影子链 | 两个游标从两端向中间走 |
| 复制随机指针 | 链 + 哈希表侧栏 | `old → new` 的映射逐条填入 |

**链表题共同的坑**：只画当前节点，不画 `next` 指向 → 用户看不出结构在变。

## 八、树族 ★★～★★★

| 题型 | 主视图 | 特有要素 |
|---|---|---|
| 前/中/后序遍历 | 树 + **访问序号** | 节点右上角标 `#1 #2 #3`（访问顺序），当前访问的节点闪 |
| 层序遍历 | 树 + **同层同色** | 层号挂左侧；**队列、`row`、`res` 三件都要画齐** |

> **层序遍历的 `row` 是硬性要求。** 它是"这一层"的实体，每轮清空重建；只画 `res` 不画 `row`，读者看到 `res.push_back(row)` 时不知道篮子里装了什么、什么时候清的空，整条链断在这里。队列那边建议把**本层与下一层用实线/虚线分开**，`n = q.size()` 才有画面依据。
| 树高 / 平衡判断 | 树 + 每节点回传值 | 值从叶子往上冒 |
| BST 查找 | 树 + **比较路径** | 每次比较把"走左/走右"的边画粗，走过的节点留痕 |
| BST 插入/删除 | 树 + 位置变化 | 新节点飞入 + 树重排动画 |
| 最近公共祖先 | 树 + 两条**上行路径** | 两条路径用两色，**第一个交汇节点**金框 |
| 序列化/反序列化 | **左右分屏**：序列 ↔ 树 | 一个游标在序列上扫，另一个在树上落点 |
| 树的构造（前序+中序） | 分屏：两个序列 + 树 | 根节点在序列里的位置用**同色竖线**贯穿 |

**坑**：树的节点位置每次重算会跳。**先算好整棵树的最宽层，定死每个节点的 x 坐标和总宽**，之后只改颜色不改位置。

## 九、图族 ★★★

| 题型 | 主视图 | 特有要素 |
|---|---|---|
| Dijkstra | 图 + **dist 表** | 每个节点下方挂 `dist`；松弛成功时那条边**闪绿并加粗**；已确定集合用实心底 |
| Bellman-Ford | 图 + **边列表** | 按轮次逐条边扫，每轮同一个颜色 |
| Floyd | **二维距离表** | 三层循环：`k` 行/列高亮（十字），`i,j` 当前格 |
| Kruskal | **边列表 + 森林** | 边按权排序，逐条考虑；成环的边**打红叉** |
| Prim | 图 + **生长中的树** | 已选集合像一团**扩张的色块**，候选边用虚线 |
| 二分图染色 | 图 + **两色** | 冲突时那条边闪红，两个端点同时红 |
| 网络流 | 图 + **残量边** | 正向边和反向边**成对显示**，反向边是虚线 |

**坑**：图节点用手动坐标会很丑。**分层布局**（按 BFS 层）或**环形布局**（节点少时）选一个；别用随机布局。

## 十、二分族 ★★

**识别**：`while (lo <= hi) { mid = (lo+hi)/2; ... }`

**主视图：线性行 + `[lo, hi]` 括号**

- 数组一行，`lo`、`hi`、`mid` 三个标签
- **`[lo, hi]` 用一段半透明色块框住**，块两端随更新收缩
- 被丢弃的那一半**变灰并整体缩小留白**（保留位置，表示"还在备选历史里"）
- `mid`：琥珀底

**辅助视图**：`lo`、`hi`、`mid`、`a[mid]`、比较结果（`a[mid] < target → lo = mid+1`）

**这一步在动什么**：**候选区间的对数级塌陷**。要让用户看清"每次砍一半"。

**二分答案（最大值最小/最小值最大）**：额外加一条**可行性轴**，`check(x)` 的结果（✓/✗）标在 `mid` 下方，让"单调性"显形。

**坑**：
- `mid` 计算写成 `(lo+hi)/2` 时会溢出，演示里要写 `lo + (hi-lo)/2`
- 二分区间写法有 `[lo,hi]` / `[lo,hi)` 两派，**图上的括号形状要和代码一致**（闭区间画 `[ ]`，左闭右开画 `[ )`）

## 十一、排序与贪心 ★★

### 11.1 排序（快排、归并、堆排序、冒泡）

**主视图：柱状图**

- 柱高 = 值，柱下标的标签
- **已排序区**用绿底 + 一条竖分界线隔开
- 正在比较的两根柱：橙色描边；交换时两根柱**横向滑动互换**
- 快排：**基准柱**用金框，`i`（小于区的边界）用虚线竖线
- 归并：**需要双行显示**（左半、右半各一行），合并时元素飞到第三行

**辅助视图**：`i`、`j`、`基准值`、`比较次数`、`交换次数`

**坑**：柱子直接跳变到新位置 → 用户看不出是交换还是移动。**必须滑动动画**。

### 11.2 贪心（区间调度、跳跃游戏、分发饼干）

**主视图：时间轴 / 区间条**

- 每个区间画成一条**横条**，在时间轴上
- 已选区间：绿；冲突被跳过：灰 + ✕
- 当前正在考虑的区间：琥珀描边
- **"结束时间"用一条竖虚线**，下一个区间的"开始时间"要和它比 —— 这个比较动作要画出来

**辅助视图**：`排序后的顺序`、`当前结束时间`、`已选数量`

**坑**：贪心的正确性靠"排序后局部最优"，所以**必须显示排序后的顺序**，否则用户不知道凭什么这样贪。

## 十四、什么时候不该画图

不是每道题都值得做演示。以下情况直接讲文字更快：

1. **纯数学推导**（快速幂、GCD、组合数学）—— 没有"过程"，只有公式
2. **答案只依赖输入规模**（数论计数）—— 图上没东西可动
3. **代码本身就是答案**（20 行以内的模板题）—— 读代码比看图快
4. **状态超过两屏**—— 用户记不住，不如分段讲

判断标准很粗暴：**如果我说不出"这一步在动什么"，就不要画。**

## 十五、多视图的组合原则

一道题最多三块区域，位置固定：

```
┌─────────────────┬──────────────┐
│                 │              │
│   主动图         │   辅助图 1    │
│  （结构 + 变色）  │  （表/栈/队列）│
│                 │              │
├─────────────────┴──────────────┤
│         变量表 + 当前语句说明     │
└────────────────────────────────┘
```

- **主动图在左上**，占 60% 以上面积 —— 它是主角
- **辅助图在右上**，只放"代码直接读写的容器"
- **变量表在底部，横排**，只装 B 级过程量（3~6 个）；A 级的 `row` / `res` / 栈 / 队列一律单独成块，不许往这里塞
- 变量表无论放哪，都必须是**紧凑胶囊**（名字和值挨着 8px），**禁止 `space-between`** 把名字和值顶到两端；竖排在右栏时**一行一个**，别三个并排横跨全宽
- 每一步的**一句话说明**贴在顶部横条，写清"算式"，不写"我在循环"

**同一个数据结构不要画两遍**。比如 BFS 里网格已经显示 `dist` 了，就不要再来一张 dist 表 —— 把数字直接写在格子里。

## 附录：可直接复制的布局函数

上面每种题型都说了"怎么摆"，但照着文字重写还是有成本。这里给四个纯函数，覆盖 90% 的坐标计算。**它们不碰 DOM，只算数字**，可以直接在 node 里测。

### A. 树 / 递归树布局（后序定宽、前序定位）

解决"树每次重算位置会跳"这个问题：**先把整棵树的宽度算死，再分配坐标**，之后只改颜色不改位置。

```js
/**
 * nodes: [{ id, parent }]，parent 为 null 表示根
 * 返回 { [id]: { x, y, depth } }
 * 单节点宽 NODE_W，层高 LEVEL_H
 */
function layoutTree(nodes, NODE_W = 74, LEVEL_H = 88, GAP = 18) {
  const kids = {};
  let root = null;
  nodes.forEach(n => {
    (kids[n.id] = kids[n.id] || []);
    if (n.parent === null) root = n.id;
    else (kids[n.parent] = kids[n.parent] || []).push(n.id);
  });

  // 1) 后序算每棵子树的"叶子占位数"
  const span = {};
  (function measure(id) {
    const ch = kids[id] || [];
    if (!ch.length) return (span[id] = 1);
    return (span[id] = ch.reduce((s, c) => s + measure(c), 0));
  })(root);

  // 2) 前序把占位换算成 x 坐标
  const pos = {};
  (function place(id, left, depth) {
    const ch = kids[id] || [];
    const w = span[id] * (NODE_W + GAP);
    // 自己是第一个子和最后一个子的中点；没孩子就居中
    if (!ch.length) {
      pos[id] = { x: left + w / 2 - GAP / 2, y: depth * LEVEL_H, depth };
    } else {
      let cursor = left;
      ch.forEach(c => { place(c, cursor, depth + 1); cursor += span[c] * (NODE_W + GAP); });
      const first = pos[ch[0]].x, last = pos[ch[ch.length - 1]].x;
      pos[id] = { x: (first + last) / 2, y: depth * LEVEL_H, depth };
    }
  })(root, 0, 0);

  return pos;
}
```

**用法**：`layoutTree([{id:'r',parent:null},{id:'a',parent:'r'},{id:'b',parent:'r'}])`
→ 根在 `x=83`（两子中点），两子分别在 `x=37`、`x=129`，`y` 分别是 0 和 88。

**关键点**：`span` 是**叶子数**不是节点数。用叶子数算宽度，兄弟节点才不会挤在一起，层级深的子树也不会把别的子树推歪。

**顺便验证了一件事**：把 `n1 → n2 → n3 → n4` 这种单链喂进去，四个节点的 `x` 全是 `37`，就是一条竖线。**这就是"线性递归别画树"的数学证明** —— 画出来是一根竖线，白占一屏，还不如直接画调用栈帧（§2.1）。

### B. 网格坐标

```js
function gridCell(r, c, CELL = 42, GAP = 4, PAD = 24) {
  const step = CELL + GAP;
  return { x: PAD + c * step, y: PAD + r * step, w: CELL, h: CELL };
}
// 整张网格的尺寸
function gridSize(rows, cols, CELL = 42, GAP = 4, PAD = 24) {
  const step = CELL + GAP;
  return { w: PAD * 2 + cols * step - GAP, h: PAD * 2 + rows * step - GAP };
}
```

**CELL 不要小于 38**，否则格子里塞不下数字（`dist`、`dp` 值、区域面积）。

### C. 栈 / 队列（横排，栈底在左）

```js
// i 是"从底数第几个"，栈底 = 0
function stackSlot(i, W = 56, GAP = 8, PAD = 16, top = 24) {
  return { x: PAD + i * (W + GAP), y: top, w: W, h: 52 };
}
// 队列同理，只是从左边进（队头在左）
const queueSlot = stackSlot;
```

**栈必须横排、栈底在左、栈顶在右**，这样"越靠右越小"的单调性才和代码里的 `pop` 方向一致。竖着画会让人以为栈是往上长的，和数组的下标方向打架。

### D. 绕线弧（链表 `next`、DP 依赖箭头、树的返回值）

```js
/**
 * 从 (x1,y1) 绕到 (x2,y2)，depth 是下探/上抬的深度
 * down=true 向下绕（向右的边），false 向上绕（向左的边）
 */
function arc(x1, y1, x2, y2, depth, down = true) {
  const cy = down ? y1 + depth : y1 - depth;
  return `M ${x1} ${y1} C ${x1} ${cy}, ${x2} ${cy}, ${x2} ${y2}`;
}
```

**三条铁律**（`rendering.md` 第四节详述，这里只重复最致命的）：

1. 向右的走下方，向左的走上方 —— 方向靠位置区分，不靠颜色
2. 终点画在目标**外面** 2px —— 目标后画会盖住箭头尖
3. 两条边水平区间重叠且深度差 < 6px 时，后一条 `depth += 24` 错开

```js
// 贪心分配深度，避免叠在一起
function assignDepth(edges, base = 30, step = 24, maxDepth = 180) {
  const used = [];
  edges.forEach(e => {
    let d = base, guard = 0;
    while (guard++ < 30) {
      const clash = used.some(u =>
        Math.abs(u.d - d) < 6 && !(e.hi < u.lo || e.lo > u.hi));
      if (!clash) break;
      d += step;
    }
    d = Math.min(d, maxDepth);
    used.push({ lo: e.lo, hi: e.hi, d });
    e.depth = d;
  });
  return edges;
}
```

**必须分两组分别调用**：向上的边和向下的边在画布两侧，物理上撞不到，混在一起分配会互相挤压、白白加深。调用前先按方向拆开，且每条边的 `lo/hi` 要保证 `lo < hi`：

```js
const ups = [], downs = [];
for (let id = 0; id <= n; id++) {
  const t = nx[id];
  if (t === null || t === undefined) continue;
  if (t < id) ups.push({ from: id, to: t, lo: cx(t) + OFF, hi: cx(id) - OFF });
  else        downs.push({ from: id, to: t, lo: cx(id) + OFF, hi: cx(t) - OFF });
}
assignDepth(ups,   40, 26, 160);   // 向上：起点就要抬过指针标签，base 大一点
assignDepth(downs, 30, 24, 180);
```

### E. 颜色：状态不要超过 5 种

整张图的语义色控制在 5 个以内，多了就没人记得住。沿用 `rendering.md` 的变量名：

| 状态 | 变量 | 用在哪 |
|---|---|---|
| 当前 / 本步改动 | `--amber` | 正在执行的那格、刚改的那条边 |
| 已纳入 / 在等待 | `--blue` | DFS 路径、窗口内、栈里的元素 |
| 已完成 / 正确 | `--green` | 答案、已确定的 dist、缓存命中 |
| 异常 / 负值 / 弹出 | `--red` | `lead < 0`、冲突边、被弹出的元素 |
| 已排除 / 历史 | 灰（`#a5a193`） | 走不通的死路、被丢弃的区间 |

**层次（层级）不要用颜色区分，用同一色相的明度递进**——BFS 的层、区间 DP 的 `len`、拓扑的层都是这个规则。
